# Ten-volume GitHub writer operations

The writer is implemented as ten GitHub Agentic Workflows, one per white-paper volume and child issue #49–#58. Each worker runs weekly, is limited to one AI credit per run and per 24 hours, and may only prepare a draft PR within its own `volumes/NN/` path and comment on its fixed child issue. The agent portion uses read-only repository/issue/PR access; only the separate safe-output job can create or update draft PRs and post the single issue comment. Workflows cannot merge PRs or close issues.

The connected Copilot account is Copilot Free and currently shows 0% included credits used. GitHub Budgets already has an account budget for All AI Credit SKUs at $0 with “Stop usage” enabled. The agent run limits further cap each worker at 1 AI credit. When the included allowance is exhausted, GitHub should block additional Copilot requests; no paid AI-credit budget is configured. The user’s Copilot activity outside this project shares the same included allowance, so the workers can stop earlier. Recheck these settings if billing configuration changes.

GitHub schedules only run from the default branch. The setup PR is based on `research/ten-strategic-questions-2026` so it can be reviewed independently from existing source PR #47. The schedule becomes active after the workflows reach the repository default branch through merging #47. Do not merge #47 automatically; it contains the author's research blueprints and requires owner review. Before first production run, verify GitHub Actions is enabled and Copilot requests using the Actions `GITHUB_TOKEN` succeed under the included-credit limit.

The writers must treat the phase-one archive as unavailable unless its files are actually committed or attached to a supported cloud source. All evidence remains public-source based. A draft PR, generated PDF, issue comment, or passing repository-file audit alone does not constitute a finished publication. The source/claim audit, manuscript and brief, reproducible analysis, exact PDF page count, PDF visual inspection, citation and accessibility checks, checksum manifest, and tested links must all be complete before a child issue is closed or a volume is represented as finished.
